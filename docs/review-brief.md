# レビュー依頼: 自作 Android ランチャー(v0.32.0)

AI(Claude / ChatGPT / Gemini)に設計レビューと今後のアップグレード案を求めるための要約。
コードを全部読む前に、まずこの 1 枚で全体像と論点をつかんでほしい。

- リポジトリ: https://github.com/snsdpen-luke/launcher
- 設計メモ(決めごと・制約の一次資料): `CLAUDE.md`
- 前任プロジェクトからの引き継ぎ(失敗の記録): `docs/handover.md`
- 規模: Kotlin 約 5,800 行、Jetpack Compose、Android Studio 不使用(Gradle 直叩き)
- 端末: Galaxy Z Fold(SM-F971Q)。カバー画面(1248x1972、555x876dp)が主戦場。開いた画面と横向きにも対応

## これは何か

作者(上村)が自分の Galaxy Z Fold のために作っている個人用ランチャー。
市販ランチャーの「アイコンの海」を捨て、**正方形のマス目(グリッド)にモジュールを置く**構造にした。
見た目の基調は「ブロックのモザイク」。壁(背景)も、見出しも、計測も、アイコンも、同じマス目に乗る。

ページは用途で 3 つ。横スワイプでループする。

| ページ | 用途 | 配色 | 主な中身 |
|---|---|---|---|
| PRIVATE | 私用 | NATURE(深い青緑)/ LEMON(グレー + 黄) | 見出し + アプリの行、時計、電池・電波・Wi-Fi・BT、歩くマスコット |
| WORK | 仕事 | 白い紙 | 予定(7 日の帯 + 日ごとの一覧)、タスク(チェック箱)、リンク、アプリ |
| DRIVE | 運転 | 濃いグレー | YouTube / Spotify / マップの大きなタイル(再生情報つき)、明るさ・音量のスライダー |

## 構造(読む順)

1. `model/Surface.kt` … 面(COVER 16x24 / COVER_WIDE 26x15 / MAIN 16x24 / SIDE 14x24)とページ
2. `model/Layout.kt` … 永続データ `LayoutState`(JSON)と **移行ステップ(v1〜v28)**。配置は (面, ページ) ごと、定義は共有
3. `model/ModuleRegistry.kt` … モジュールの契約 `ModuleSpec`(種類・既定サイズ・タップ・描画)とイベント
4. `ui/ModuleGrid.kt` … グリッド本体。タップ・長押し・ドラッグ・入替・リサイズを一元処理。モジュール本体は受動
5. `ui/modules/*.kt` … 各モジュール(時計 / アプリ行 / 見出し / リンク / 計測 / 予定 / タスク / スライダー)
6. `ui/Theme.kt` … 配色 `Palette`(演出の有無もここのフィールドで切る)
7. `LauncherApp.kt` … 画面全体の配線(ページ切替、ダイアログ、イベント処理)
8. `data/` … アプリ一覧、メディアセッション、計測、カレンダー。`notif/` … 通知リスナー

## 設計上の主な決定(理由つき)

- **マスは正方形、一辺は幅と高さの小さい方から決める**。余りは両側の余白。半端なマスは作らない
- **配置は面ごとに独立**(カバー縦 / カバー横 / 開いた時の左)。初回だけ縦の配置から自動生成し、以後は別々に育つ
- **開いた画面 = 左に独立配置 + 右に「窓の置き場」**。ホームアプリは Android の分割画面の相棒になれない(実機で確認)ので、左のアプリをタップすると **Samsung の自由配置ウィンドウ**を右側の矩形に出す(`setLaunchBounds`)
- **常時アニメと定期の読み直しは表示中だけ**(`WhileResumed`)。裏では CPU 0.0% を実機で確認
- **毎秒・毎 0.7 秒の状態は自分の Composable に閉じる**。グリッド本体で読むと全モジュールが再構成される
- **レイアウトのグリッド構造を変えたら必ず移行ステップを足す**(`LAYOUT_VERSION`)。既定値の省略で移行が空振りした事故が過去にあり、JSON は `encodeDefaults = true`
- **ステータスバーは隠す**。代わりに電池・電波・Wi-Fi・BT の 2 マスの計測と、通知の明滅(アイコンの後ろの 1 マスが橙で明滅)
- 文字はフォントの上下余白でマス目とずれるので、時計は `TextMeasurer` + `drawText` で自分で描く
- 再生情報(曲名・ジャケット・再生/停止)は **メディアセッション**から取る(通知アクセスがあれば読める)。本物の音の拍は取れないので、拍の演出は一定テンポの擬似

## 分かっている限界・未解決

- YouTube の映像をタイルに流すことはできない(YouTube が映像を外に出さない)。サムネイルまで
- 自由配置ウィンドウは「分割」ではない。ホームボタンで丸いアイコンに縮む。左右の入替は未実装
- 横向きの自動配置は「縦の左列 → 右列の順に、幅 8 の縦の帯へ流す」だけ。手直し前提
- 通知の明滅は、他のアプリが通知を消すと消える(作者の QuietInbox がそうだったので削除した)
- 明るさの変更は WRITE_SETTINGS の許可が要り、自動明るさを切ってしまう
- メイン画面は実機で数回しか確認していない。カバー画面ほど作り込んでいない
- ボード(`board:`)は廃止済みだがコードが残っている

## レビューしてほしいこと(論点)

1. **構造**: `ModuleSpec` + 絶対セル配置の骨格は、この先モジュールを 20 種類に増やしても持つか。破綻するならどこか
2. **永続化と移行**: 28 段の移行ステップを積み上げる方式の妥当性。別の設計(スキーマ版 + 再生成など)にすべきか
3. **性能**: モザイクの壁(384 マスの Canvas)+ 拍の演出(1 秒 20 回)+ 毎秒の時計。電池への影響をどう見積もり、どう測るか
4. **開いた画面の使い方**: 「左に独立配置、右に自由配置ウィンドウ」より良い案があるか。Samsung 固有機能への依存をどう扱うか
5. **通知**: 通知リスナーで件数と本文を読む現状の作り。ステータスバーを隠したままで見落としを防ぐ別案
6. **配色と演出の管理**: `Palette` のフィールドで演出を切る方式は、配色が 10 個になっても破綻しないか
7. **今後の機能**: 運転・仕事・私用の 3 ページ構成を前提に、作者が気づいていない「あると効く」モジュールは何か

回答は「一般論」ではなく、このコードのこの箇所を指して、こう変えるとこうなる、の形で頼みたい。
反対のための反対は不要。良い所は良いと言ってよい。
